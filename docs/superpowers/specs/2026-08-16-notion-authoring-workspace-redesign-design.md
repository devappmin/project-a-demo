# Notion 대화 집필 공간 개편 설계

## 목적

사용자와 디자이너가 영어 내부 키, 관계형 대화 조각, 순서 숫자, JSON을 직접 관리하지 않고 Notion에서 한국어 문서로 캐릭터와 장소별 대화를 공동 집필한다. 기존 `Characters`, `Dialogue Scenes`, `Dialogue Blocks` 세 데이터베이스는 현재 문서형 대화 구조에 맞춰 활성 데이터베이스 두 개로 정리한다.

## 확정 구조

### 1. `캐릭터 설정`

기존 `Characters` 데이터베이스를 재사용한다. 캐릭터 한 명당 페이지 하나를 사용한다.

기본 화면에는 다음 속성만 표시한다.

- `캐릭터 이름`: 제목
- `역할`: 짧은 설명
- `상태`: `초안`, `검토`, `확정`
- `담당자`: 사람

기존 `character_key`, `default_expression`, `expressions` 값은 기존 페이지 본문의 접힌 `이전 구조 참고` 구역에 한 번 보존한 뒤 데이터베이스 속성에서는 제거한다. 새 작성자는 영어 내부 키를 관리하지 않는다.

`캐릭터 설정 템플릿` 본문은 다음 구역을 가진다.

- 핵심 한 문장
- 성격과 욕망
- 말투와 자주 쓰는 표현
- 다른 인물과의 관계
- 표정과 감정 표현
- 이야기에서의 역할

표정은 한국어 이름과 의미를 본문에 적는다. 게임 반영 시 Codex 또는 Claude가 저장소의 서사 용어 참고서와 대조하며, 확인 없이 내부 키를 만들지 않는다.

### 2. `장소 대화 문서`

기존 `Dialogue Scenes` 데이터베이스를 재사용한다. 장소 하나 또는 긴밀한 이야기 묶음 하나당 페이지 하나를 사용한다.

기본 화면에는 다음 속성만 표시한다.

- `장소·장면`: 제목
- `장소 태그`: 선택
- `상태`: `초안`, `검토`, `확정`
- `담당자`: 사람

기존 `scene_key`, `start_flow` 값은 기존 페이지 본문의 접힌 `이전 구조 참고` 구역에 한 번 보존한 뒤 데이터베이스 속성에서는 제거한다. 내부 키와 흐름 ID는 AI가 저장소에서 유지한다.

`장소 대화 템플릿`은 다음 순서를 사용한다.

1. 상단 콜아웃: 한 페이지에 같은 장소의 입장, 인물 대화, 물건 조사를 함께 적는다는 짧은 안내
2. `장소 개요`: 이 장소의 이야기 목적과 주요 등장인물
3. 제목 1 `트리거 · <이름>`
4. 제목 2 `이벤트 · <이름>`
5. 이벤트 바로 아래 인용 블록의 `발생`, `조건`, `결과`
6. 제목 3 `흐름 · 시작`과 대사, 선택지, 흐름 이동, `끝`
7. 구체적 조건 이벤트 아래에 선택적인 `이벤트 · 그 외`

템플릿은 선택 이후 여러 문단, 두 번째 선택, 분기 합류를 예시로 보여 준다. 캐릭터와 표정은 `레티 [불안]: ...`처럼 한국어로 쓴다. 조건과 결과는 인용 블록에만 쓰고, 연출 논의와 대안 문장은 Notion 댓글로 남긴다.

### 3. `Dialogue Blocks` 폐기

새 구조에는 대사 한 줄당 페이지가 필요하지 않다. 기존 거울 장면의 여섯 블록을 `거울 조사` 장소 문서 본문으로 의미 보존 이전한다. 다음을 확인한 후 `Dialogue Blocks` 데이터베이스 전체를 Notion 휴지통으로 이동한다.

- 모든 기존 대사, 선택지, 효과, 종료가 새 문서에 존재한다.
- 화자와 표정이 한국어로 표시된다.
- 선택지 목적 흐름과 효과 적용 시점이 유지된다.
- 기존 `거울 조사` 페이지 하나만으로 장면을 읽을 수 있다.

휴지통 이동은 영구 삭제가 아니며 Notion에서 복구할 수 있다. 이전 검증 전에 데이터베이스를 휴지통으로 보내지 않는다.

## 협업 흐름

1. 작성자는 `장소 대화 템플릿`을 복제한다.
2. 사용자와 디자이너가 본문과 인용 블록을 함께 작성하고 댓글로 논의한다.
3. 합의된 댓글 내용은 본문 또는 인용 블록으로 옮긴다.
4. Codex 또는 Claude가 페이지를 읽어 저장소의 정규화 JSON을 갱신한다.
5. 수동 dry-run에서 한국어 매핑과 추가·변경·변경없음 목록을 확인한다.
6. 승인 뒤에만 로컬 런타임 스냅샷을 게시한다.

Notion integration 토큰, 실시간 sync, 데이터베이스 relation, 블록별 order 필드는 사용하지 않는다.

## 변경 안전성

- 기존 항목을 먼저 새 본문으로 이전하고 사람이 읽어 의미를 확인한 뒤 구형 DB를 휴지통으로 보낸다.
- 기존 기술 속성 값은 페이지 안의 접힌 참고 구역으로 옮긴 뒤 속성을 제거한다.
- 새 템플릿을 복제해 제목 계층, 인용 블록, 선택지와 재합류 구조가 유지되는지 확인한다.
- 외부 Notion 변경 뒤 저장소의 `docs/dialogue-authoring-guide.md`에서 기존 세 DB를 읽기 전용으로 남긴다는 문구를 새 활성 구조로 갱신한다.

## 완료 조건

- 기획안 아래에는 활성 DB `캐릭터 설정`, `장소 대화 문서`만 남는다.
- 두 DB에 한국어 기본 템플릿이 존재하고 복제할 수 있다.
- `거울 조사`가 한 페이지짜리 문서형 대화로 읽힌다.
- `Dialogue Blocks`는 이전 검증 후 휴지통에 있으며 복구 가능하다.
- 기존 레티 데이터가 `캐릭터 설정` 페이지에 보존된다.
- 저장소 가이드가 실제 Notion 구조와 일치한다.
